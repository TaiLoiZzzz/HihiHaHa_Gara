★ ĐIỂM CỐT TỬ: LOCAL ACID TRANSACTION TRONG POSTGRESQL ★

VNPay Báo Tiền Về ➔ Mở Transaction Lưu Tiền & Tạo Thư Outbox

💳 VNPay IPN ➔ ⚙️ Backend ➔ 🐘 PostgreSQL {BEGIN...COMMIT}

Chuyện gì xảy ra? Khách chuyển tiền xong, VNPay bắn một tin báo ngầm (Webhook IPN) sang Backend. Backend mở ngay một Transaction trong PostgreSQL làm cùng lúc 2 việc:

  1. Đổi dòng trong bảng payment_transactions từ PENDING sang SUCCESS (Đã có tiền).
  2. Chèn 1 dòng vào bảng outbox_events mang trạng thái PENDING (Dặn dò Worker đi trừ kho).
💡 Tại sao bắt buộc phải dùng Transaction ở đây?
Vì 2 lệnh này nằm chung khối BEGIN ... COMMIT. Nếu server bị sập nguồn đúng lúc này, cả 2 cùng biến mất (Rollback). Không bao giờ xảy ra tai họa nhận được tiền của khách mà quên tạo thư đi trừ kho!
Khối Transaction Cục Bộ Tuyệt Đối: PostgreSQL ACID (All or Nothing) 
BEGIN; -- BẮT ĐẦU GIAO DỊCH NGUYÊN TỬ

-- 1. Cập nhật tiền đã vào tài khoản gara
UPDATE payment_transactions 
SET status = 'SUCCESS', vnp_bank_code = 'NCB', completed_at = NOW() 
WHERE vnp_txn_ref = '20261002_WO0089';

-- 2. Tạo bức thư Outbox dặn dò trừ kho (NẰM TRONG CÙNG TRANSACTION)
INSERT INTO outbox_events (
    aggregate_type, aggregate_id, event_type, payload, processed_status
) VALUES (
    'WORK_ORDER', 
    'WO-20261001-0089', 
    'PAYMENT_COMPLETED', 
    '{"amount": 2808000, "part_code": "04465-06100", "qty": 1}', 
    'PENDING'
);

COMMIT; -- LƯU VĨNH VIỄN XUỐNG ĐĨA CỨNG!
🔬 Soi Ruột 2 Bảng Trong PostgreSQL Vừa Thay Đổi Xong:
• Bảng payment_transactions: status đổi thành SUCCESS (ĐÃ CÓ TIỀN)
• Bảng outbox_events: xuất hiện dòng mới PENDING (CHỜ WORKER NHẶT ĐI)
(Lưu ý: Lúc này phía MongoDB xe vẫn là UNPAID và kho vẫn còn 4 bộ vì MongoDB nằm ở database riêng, chưa đụng tới!)

Outbox Worker Thức Dậy ➔ Quét Thư Bằng Partial Index

🐘 outbox_events ➔ 🔄 Worker ngầm (SKIP LOCKED)

Chuyện gì xảy ra? Một tiến trình chạy ngầm tên là Outbox Worker thức dậy mỗi 2 giây. Nó vào bảng outbox_events tìm các bức thư đang PENDING để nhặt đi xử lý. Nó dùng lệnh khóa SKIP LOCKED để nếu có nhiều worker cùng chạy thì không tranh nhau 1 bức thư.

⚡ Bí mật tốc độ của Partial Index: Bảng outbox sau này có thể chứa cả triệu dòng cũ. Nhờ có WHERE processed_status = 'PENDING', PostgreSQL chỉ quét trong đúng 5 - 10 dòng đang chờ, tốc độ nhanh như chớp dưới 0.1 mili-giây mà không tốn RAM!

Lệnh SQL Worker quét lấy mẻ 20 sự kiện: Worker Polling 
SELECT * FROM outbox_events 
WHERE processed_status = 'PENDING' 
ORDER BY created_at ASC 
LIMIT 20 
FOR UPDATE SKIP LOCKED;

Cập Nhật MongoDB & Trừ Kho Vật Lý (Khử Trùng Lặp Idempotent)

🔄 Worker ➔ 🍃 MongoDB (Đổi PAID) ➔ ⚡ Redis (Xóa khóa)

Chuyện gì xảy ra? Worker cầm nội dung bức thư sang nạp vào MongoDB:

  1. Đổi trạng thái xe thành PAID (Đã trả tiền).
  2. Trừ kho vật lý má phanh từ 4 bộ xuống 3 bộ.
  3. Vào Redis xóa chìa khóa giữ chỗ hold vì khách đã lấy đồ thật.
🛡️ Chống lỗi mạng lag (Idempotency): Điều kiện payment_status: { $ne: 'PAID' } nghĩa là "Chỉ cập nhật khi chưa phải là PAID". Nếu mạng lag gửi bức thư này 2 lần, MongoDB thấy xe đã PAID rồi sẽ không làm gì cả $\rightarrow$ Không bao giờ bị trừ thành 2 bộ má phanh!
Code Mongoose cập nhật có điều kiện: MongoDB Node.js Driver 
// 1. Chỉ cập nhật khi trạng thái xe KHÔNG PHẢI LÀ PAID ($ne)
const res = await WorkOrder.updateOne(
    { order_code: 'WO-20261001-0089', payment_status: { $ne: 'PAID' } },
    { $set: { payment_status: 'PAID', current_status: 'PAYMENT_CONFIRMED' } }
);

if (res.modifiedCount === 1) {
    // 2. LẦN ĐẦU TIÊN: Trừ tồn kho vật lý má phanh từ 4 xuống 3!
    await InventoryItem.updateOne(
        { part_code: '04465-06100' }, { $inc: { stock_quantity: -1 } }
    );
    // 3. Xóa key giữ chỗ trên Redis
    await redis.del('hold:WO-20261001-0089:04465-06100');
}
🔬 Soi Ruột MongoDB & Redis Sau Khi Trừ Kho:
• Hồ sơ xe (work_orders):
payment_status = "PAID"
• Kho má phanh (inventory_items):
stock_quantity = 3 bộ (ĐÃ TRỪ -1)
• Tủ Redis: KEY hold:WO0089 ➔ ĐÃ XÓA GIẢI PHÓNG!

Đóng Dấu Thư Outbox ➔ Socket.io Báo Về Điện Thoại Khách

🔄 Worker ➔ 🐘 outbox_events (PROCESSED) ➔ 📱 Điện thoại Khách

Chuyện gì xảy ra? Worker quay lại PostgreSQL đóng dấu lên bức thư: PROCESSED (Đã xong nhiệm vụ). Ngay lập tức, máy chủ phát sóng WebSocket (Socket.io) về điện thoại của khách: Màn hình tự động hiển thị dấu tích xanh thông báo thanh toán thành công kèm nút tải hóa đơn VAT!

Lệnh cập nhật trạng thái bức thư đã xử lý xong: PostgreSQL Update 
UPDATE outbox_events 
SET processed_status = 'PROCESSED', processed_at = NOW() 
WHERE event_id = 'e7b8c9d0-1234-5678-9abc-def012345678';

// Phát sóng thời gian thực về máy khách
io.to('room:order:WO-20261001-0089').emit('PAYMENT_COMPLETED', {
    order_code: 'WO-20261001-0089',
    amount: 2808000,
    status: 'PAID'
});
